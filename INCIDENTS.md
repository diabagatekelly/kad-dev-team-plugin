# Incidents

What a real run did that a rule in a skill now prevents. Each skill cites
the number alone, `(incident 14)`, and states its rule in general terms;
the story lives here, once, so a reader of a skill is not primed toward
one project's shape and a rule's origin is still on record. The runs:
run 1 and run 2 (2026-10, two repositories), run 3 (2026-11-01, the first
on this plugin's full roster), slice 2 (2026-11-07 and 08, the second
slice of the third repository) and slice 2's fix round (2026-11-10, the
first run of the 0.14 list). Reviews: `.synthesis/handoff-run3.md`,
`.synthesis/handoff-slice2.md` and the audit repository's reviews.

1. **Run 3.** The slice reviewers each read one side of an exchange-once seam and missed a provider record left orphaned, three runs running. Rule: read the changed modules in full, with every test that exercises them; the diff says what moved, the module says whether it is right.
2. **Run 3.** An exchange timed out after the provider had completed it; the retry got a token-already-used error and the record stayed orphaned with nothing revoked. Reviewers read the success path and the failure path one at a time. Rule: an exchange that creates something remote carries one idempotency key and the refused repeat is reconciled against what the provider holds.
3. **Run 3.** A fixer's one `sed -i` over the tree renamed a seam test and rewrote a function body that happened to match. Rule: no tree-wide substitution; grep the old name before the commit; shell edits are counted.
4. **Slice 2.** A chunk's builder reported one shell edit and had made nine. Rule: the gate replays the transcript and writes the counted number beside the reported one.
5. **Slice 2.** A chunk was committed on a red test run: the test command was chained to the commit through a grep that exited 0, and the report said the suite was green. Rule: the last test run before a commit is one Bash call whose output is read; never the run and the commit on one line.
6. **Slice 2.** The builders consulted the architecture map every chunk and still redefined three test helpers across ten files, because the map indexed the source tree only. Rule: the map carries a test-support tier; a helper that exists is imported.
7. **Run 2, run 3, slice 2.** Brittle assertions (a test retyping an on-screen sentence or markup) ran at about 0.6 per test in run 3 and slice 2 against 0.1 in run 2's suite. Rule: user-facing strings exported from one module and asserted by the constant; the test-quality review's 0.30 bar.
8. **Slice 2.** The orchestrator's own thread averaged about 427k cache-read tokens per call over 396 calls, 44% of the slice's cost, nearly all of it per-chunk mechanics. Rule: one chunk runner per chunk carries the round; the orchestrator keeps the records (the v4 design's D9 phase 2, built once the thread passed about 250k).
9. **Slice 2.** An intermittent test failure was sighted four times before anyone looked for its cause. Rule: a gate failure that passes on a re-run goes to one gate fixer told to find the cause, not the symptom.
10. **Slice 2.** Two smoke agents started the app on the owner's real data directory and login credential store; nothing changed, by luck and by checksum. Rule: every agent that starts the app does so through `scratch_run.py` with every data path inside a scratch folder and made-up data; the orchestrator hashes the real data around each launch.
11. **Run 3.** The UI slice reached the five-hour loop budget at chunk 7 of 8 and the owner lifted it. Rule: eight hours for a UI-touching slice, five otherwise (decided 2026-11-06).
12. **Run 3 and slice 2.** Run 3's smoke reports said PASS when no browser had ever answered; slice 2 ran with no browser because the sandbox field said so and the flow was allowed to go on. Rule: the sandbox check names the browser; a UI-touching slice without one is a question at A; a smoke report never says PASS over an unavailable browser.
13. **Run 3 and the 2026-11-07 fix session.** Sessions started from a shell carrying another session's `CLAUDE_CODE_CHILD_SESSION` saved no transcript; both reached E with the cost not measured and nothing for the audit to read, and run 3's loop session ended without a SessionEnd. Rule: the launcher drops the marker (0.13.1); the audit snapshot runs after every records commit, not at a session end that may never come.
14. **Slice 2.** A deferral ("changing a general rule") went to requirements with six reviewers accepting it as the document's; a cold read found the first choice permanent and a misclick with no undo. Rule: every deferred item carries the owner's "Usable without it" sentence or goes to the owner before the build; the slice reviewers restate every accepted deferral as a finding.
15. **Slice 2.** The orchestrator dumped every tab of the owner's spreadsheet into the scratchpad with one command; the whole sheet is in that session's transcript for good. Rule: nothing opens a listed source but `source_scan.py describe` (shape only, one tab) and `scan`.
16. **Slice 2.** The requirements took one real row of the owner's file (a name and an amount) as an example; the slice, the design, the story, the plan's test names and thirteen test files carried it, and the criterion saying nothing of the file was in the repository was written five minutes after two documents had broken it. Rule: every example invented and said so; the scan at readiness, every chunk gate and before every push.
17. **Run 3 and slice 2.** Run 3 wrote the readiness route's bullet under the chunk-loop entry; slice 2 appended its A to E lines under its second backward route, and the log checker read all sixty loop calls as unlogged. Rule: the chunk-loop entry opens after the gate's last route; one bullet names the routes.
18. **Slice 2.** Removing a value from history was improvised: a 42-commit rewrite was verified clean, and the record's own log bullet then named the values removed, so they were pushed in the log. Rule: only `delivery`'s "Removing a value from history", on the owner's words; no report or record ever names a removed value.
19. **Slice 2.** One in four actionable findings was a regression the fixers had introduced (25%). Rule: the slice review measures regressions per actionable finding; the light cadence sends fixes to the chunk's own builder.
20. **Run 3.** The E line carried the planning session's cost as if it were the run's. Rule: a total that does not cover the loop's own sessions is never written.
21. **Slice 2.** Eight happy-dom smoke runs and six reviewers passed a screen whose confirmations and failures drew 2,000 px above the viewport; the owner found it in the first real browser session. Rule: UI chunks are smoked in the real browser with a screenshot per state; the criteria are walked in the browser at D.
22. **Slice 2.** The mockups were never rendered, and the layout a long table forces was invisible until the built screen. Rule: screen designs are rendered and screenshot at the default width and at 360 px with a month's worth of rows.
23. **Run 3.** The design kept its failure paths under headings that dropped the words Strategic and Tactical and failed the readiness gate until the headings were renamed. Rule: the two headings carry exactly those words.
24. **Run 3.** The design wrote that tests run against in-memory implementations of the source and the stores; the builder followed it, and the slice review's fake inventory was the finding. Rule: the design names the slice's own boundaries and never widens the fakes.
25. **Run 3.** The technology bootstrap left six categories "not yet decided" and was re-entered six times mid-build (a server, the vendor client's pin, a crypto library, the OS credential tool, a log writer, a test DOM). Rule: one default per category a later chunk may force, approved once as a set.
26. **Run 3.** The README said no CI ran the checks one commit after the CI workflow landed. Rule: the CI sentence is written from the workflow file's presence.
27. **Slice 2's fix round.** Two structural Highs at the slice review (a page script with four reasons to change, a use case doing five jobs) were fixed by a fixer in the last round, and the independent cold read then scored readability one point lower than before the split. Rule: at the slice review a size finding whose fix is a split is `needs-decision (software-architect)`.
28. **Slice 2's fix round.** The source scan on a fourteen-tab workbook listed as `all`, with no `Listed at` commit, found 12,870 hits in 311 files, ordinary words of the CI file and the README matching cells of unrelated tabs; the owner held the listing. Rule: the row names the one tab the stage read; a one-word cell counts alone only as a name.
29. **Slice 2's fix round.** The Definition of Done's README check passed on headings while the README's "does not" list named a criterion the round had built. Rule: the list is read against the slice's acceptance criteria.
30. **Slice 2's fix round.** The mutation runner read only node's TAP output and reported every kill as a runner error; a `--base` the clone lacked dropped the in-diff column without a word. Rule: the runner reads the spec reporter too and says what it could not do.
