## The direction the user chose (2026-10-12)

Settled after weighing "remove the human orchestrator entirely" against
"keep some human orchestration without bottlenecks":

- Planning stages (framing, requirements, slicing, design) stay
  human-gated. Deciding what to build is the user's job and they keep it.
- The code writer (tdd-coach, through the orchestrator's
  quarantine/grade/combine flow) is meant to be fully autonomous: never
  blocks on a question, assumes visibly, escalates in its report.
  Quarantine = two subagents implement the same slice in isolated
  worktrees; Grade = mechanical checks plus a blind pairwise judge;
  Combine = the orchestrator takes the best of each and submits.
- A vertical slice stays the unit of delivery (one PR = one slice). The
  implementer may get the whole unit (slice set, requirements, designs,
  architecture map) as read context, but does not batch slices.
- One plugin, not two: lightness is a policy switch on orchestration.
  Experiments on two repos are fine.
- Agreed fix order for the plugin itself (not started, except the first
  tool): a mechanical validation gate in front of Grade
  (`tools/validation_gate.py`, built, not yet wired into the
  orchestrator's Grade step), promote `tools/pairwise_judge.py` to the
  arbiter, full reviewer pass on the finalized build, diversify candidate
  inputs, sandbox the code-writing agent.

## Why the audit

Before trusting the suite as that validation layer, the user asked
whether it would actually catch a regression. The audit
(`AUDIT-2026-10-12.md`) found: bars were "last score seen" recorded under
calibration mode while the gate scores under a different mode; a 0.1
tolerance on the aggregate let one grader fail forever; 227 of 532
graders judged `last_message`, where the judge is noisy on long text;
three phase-3 chains were answered by their frozen history; the tdd
cases' process graders could be bypassed and were blind to Bash writes;
several prompts or fixtures pointed at the plant. `TODO.md` turns that
into phases A–G.

## Running evals: what we learned the hard way

- **Windows cannot run the gate.** The gate grants Bash to every case
  and the CLI refuses a shell grant without a sandbox backend. The CLI
  still writes a scored result for the refused zero-turn run; both tools
  now treat it as an error. Review cases run by hand without the Bash
  grant work on Windows.
- **GitHub workflow**: Ubuntu 22.04 image (24.04's AppArmor restriction
  on unprivileged user namespaces breaks bubblewrap's loopback setup;
  the model then quietly reviews with Read/Grep and tdd cases cannot run
  tests), a `bwrap` probe step before anything is spent, 300-minute job
  limit (a tdd case can take 30 minutes a run, and the gate re-runs a
  suspect case at three runs). Results upload as the `eval-results`
  artifact. Costs seen: about $0.45 per review case including the judge;
  the full 36-case set came to $16 before the tdd cases finished.
- **API key facts**: this Console issues user-scoped keys
  (`sk-ant-usr-…`) that need an `anthropic-workspace-id` header, which
  the workflow sends from an `ANTHROPIC_WORKSPACE_ID` secret through
  `ANTHROPIC_CUSTOM_HEADERS`. `gh secret set` run through the Claude
  session stores an empty value (no stdin); run it in a normal terminal
  or pass `--body`. Workspace ID used today: `wrkspc_01WV56WExWQc568sT7R2tcws`.
- **Credits ran out** on 2026-10-13 and the user chose WSL2 on their
  Claude subscription over buying more. Both keys created that day were
  disabled in the Console and both repository secrets deleted. The keys
  were pasted into the chat, so the 2026-10-13 session transcript under
  `~/.claude/projects/…/1678aed6-….jsonl` contains them; the user plans
  to delete that session once this hand-off is done.
- **Reading CI results**: `tools/summarize_results.py <dir>` prints
  per-case score, cost, errors and failed graders;
  `tools/report_evidence.py <dir> <case> [chars] [grader-regex]` prints
  what the judge was shown for each failed grader, from `report.html`
  (the only place the review text survives when traces are missing).
- **Judge noise**: the CLI itself warns that LLM judges are noisy on
  files over about 10k characters. Several restraint failures were the
  judge reading "a finding that mentions `main/`" as "main/ reported as
  a violation". Write criteria that say what does not count.
- **Editing from Windows**: the Bash tool's heredocs halve backslashes;
  write any script with regexes using the Write tool, then run it.
  `gh run view --log` works only after the job completes. Console
  output is cp1252; the tools reconfigure stdout to UTF-8.
- Every synthetic-trace test for the regex graders lived in session
  scratch (`test_b.py`, `fix_run5.py`); the patterns themselves are in
  the case files and `TODO.md` records what each was checked against.
