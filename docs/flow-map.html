How kad-dev-team takes a new project from an idea to a pull request

Read top to bottom. Each row is one stop: what happens, which persona and skill does it, and which scripts decide something without a model. As of kad 0.17.1.

A model chip reads persona · skill, with where it runs: inline is the main session following the skill, agent is a separate agent launched on Sonnet or Opus. A tool chip is a script or command whose output is taken as it prints: the model runs it and does not second-guess it.

Every turn: the orchestrator finds the next step

The owner says "what's next" and never has to name a persona. The orchestrator is a skill the main session loads. It inspects what exists, routes exactly one step, logs it, and reports.

The scripts, and what each one decides without a model

All but two live beside the orchestrator skill; screen_check.py is also copied into a project with a screen, so its CI can run it. The model runs them and carries their last line; it does not re-count or overrule them.

ScriptDecidesWhere
sandbox_check.pyWhether the session is fenced from the machine's keys and the networkA, and before every launch
readiness_check.pyWhether the planning documents are complete enough to build from (eleven checks)A

validation_gate.pyWhether a commit passes: suite, typecheck, lint, coverage, the eight check categories against their baselines, scope, test namesC after every build and fix; D
